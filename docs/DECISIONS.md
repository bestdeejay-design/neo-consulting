# DECISIONS — Решения по проекту (ADR-lite, L1)

> **RU:** L1-уровень решений. Вместо полного набора ADR — один сводный файл с
> ключевыми решениями, их контекстом и последствиями. Формат упрощён от ADR-000.

## D-001 — Статический HTML/CSS/JS без сборщиков

- **Status:** Accepted · **Date:** 2026-08-13 · **Owner:** исполнитель
- **Context:** лендинг из 14 блоков, без бэкенда и динамики сервера. Сборщики
  (Vite/Webpack) добавляют зависимости и шаг сборки, не нужные для статики.
- **Decision:** пишем чистый HTML/CSS/JS, запуск через `python3 -m http.server`.
- **Consequences:** проще публикация на GitHub Pages; нет npm-зависимостей.
  Минус: без модульной сборки JS держим в одном `js/main.js`.

## D-002 — Локальные изображения в `assets/img/`

- **Status:** Accepted · **Date:** 2026-08-13 · **Owner:** исполнитель
- **Context:** бриф требует ноль внешних URL и тестовую графику (аватары, офис, OG).
- **Decision:** все картинки — локальные файлы в `assets/img/`, генерируются скриптом.
- **Consequences:** сайт автономен, индексируется офлайн; OG 1200×630 собирается
  скриншотом hero после финальной вёрстки.

## D-003 — Контент строго на русском, первым языком

- **Status:** Accepted · **Date:** 2026-08-13 · **Owner:** исполнитель
- **Context:** ЦА — российские ИП/ООО, бриф на русском, тон «мы/вам».
- **Decision:** весь текст сайта на русском; технические идентификаторы (OG, JSON-LD,
  `id` секций) — латиницей по стандартам.
- **Consequences:** понятно ЦА; SEO под русскоязычные запросы.

## D-004 — Публикация на GitHub Pages из main/root

- **Status:** Accepted · **Date:** 2026-08-13 · **Owner:** исполнитель
- **Context:** нужен бесплатный хостинг статики с HTTPS и простым деплоем.
- **Decision:** репозиторий `bestdeejay-design/neo-consulting`, Pages из ветки
  `main`, корень (`/`).
- **Consequences:** деплой = push в main; нет CI-конфигурации. Минус: нет
  собственного домена (вне скоупа).

## D-005 — Лицензия MIT

- **Status:** Accepted · **Date:** 2026-08-13 · **Owner:** исполнитель
- **Context:** открытый репозиторий, требуется явная лицензия для community health.
- **Decision:** `LICENSE` MIT, владелец `bestdeejay-design`, 2026.
- **Consequences:** максимальная свобода повторного использования.

## D-006 — Одностраничная структура лендинга

- **Status:** Accepted · **Date:** 2026-08-13 · **Owner:** исполнитель
- **Context:** 14 блоков брифа — это один просмотр, без разделения на страницы.
- **Decision:** один `index.html`, навигация по якорям (`#section`).
- **Consequences:** простая SEO-структура (одна страница + sitemap из 1 URL);
  якоря проверяются в TEST_PLAN T11.

## D-007 — Подход design-taste с токенами

- **Status:** Accepted · **Date:** 2026-08-13 · **Owner:** исполнитель
- **Context:** нужен премиальный, не «AI-шаблонный» вид при статике и Lighthouse ≥ 90.
- **Decision:** фаза Design Read → токены → uniqueness gate → реализация; все цвета
  в `:root`, ноль raw-hex вне токенов (проверка `meta_audit.py`).
- **Consequences:** единая палитра, лёгкая правка; контраст WCAG ≥ 4.5:1 по дизайну.

## D-008 — Секция «Разборы» на главной (перелинковка статей)

- **Status:** Accepted · **Date:** 2026-10-26 · **Owner:** SEO-аудит
- **Context:** 7 материалов не имели входящих ссылок с главной (только через
  `/materials/`), из-за чего ссылочный вес размывался, а робот реже переобходил статьи.
- **Decision:** добавляем секцию `#guides` с тремя ключевыми разборами и ссылкой
  на хаб материалов; пункт «Разборы» появляется в мобильном меню и подвале.
- **Consequences:** коммерческая и справочная части сайта связаны в один граф.
  Минус: главная выросла на один экран (17 секций вместо 16).

## D-009 — `presentation/` закрыта от индексации

- **Status:** Accepted · **Date:** 2026-10-26 · **Owner:** SEO-аудит
- **Context:** служебная презентация (416 слов, без description и разметки) могла
  попадать в индекс тонкой страницей и конкурировать с лендингом.
- **Decision:** `meta robots="noindex, follow"`, canonical, description, OG/Twitter,
  разметка `PresentationDigitalDocument`; из sitemap исключена.
- **Consequences:** индекс чище, страница по-прежнему доступна по прямой ссылке
  и корректно выглядит в мессенджерах. Важно: `Disallow` в robots для неё не ставим —
  иначе робот не увидит `noindex`.

## D-010 — Отказ от Google Fonts на страницах материалов

- **Status:** Accepted · **Date:** 2026-10-26 · **Owner:** SEO-аудит
- **Context:** 8 страниц материалов подключали Inter и Space Grotesk с
  `fonts.googleapis.com` (2 preconnect + CSS-файл). Это сторонние соединения,
  риск недоступности в РФ, удар по LCP и противоречие заявлению «ноль внешних запросов».
- **Decision:** удаляем внешние ссылки, переводим `--font-body` и `--font-display`
  на системные стеки из `css/tokens.css` (Georgia-серифный дисплейный + системный
  без засечек); в аудит-скрипте появляется запрет внешних подресурсов.
- **Consequences:** быстрее первый экран, единый вид с главной, меньше зависимостей.
  Минус: типографика чуть менее «авторская», чем у Space Grotesk.

## D-011 — E-E-A-T-слой: автор, даты, организация

- **Status:** Accepted · **Date:** 2026-10-26 · **Owner:** SEO-аудит
- **Context:** в статьях автором была организация, не было видимых дат, а узел `#org`
  в JSON-LD был только ссылкой по `@id` и на странице не определялся.
- **Decision:** автор — `Person` (Надежда Жданова, генеральный директор) с
  `worksFor → #org`; полный узел организации и `Blog` добавляются в `@graph`
  каждой страницы; в hero появляется строка «Опубликовано / Обновлено / Автор»;
  `dateModified` = 2026-10-26 (страницы действительно изменены).
- **Consequences:** поисковик видит автора-человека и дату актуальности — критично
  для налоговой тематики. Минус: дату обновления нужно поддерживать честно,
  при каждом содержательном изменении материалов.

## D-012 — SEO-аудит в CI как регрессионный тест

- **Status:** Accepted · **Date:** 2026-10-26 · **Owner:** SEO-аудит
- **Context:** SEO-метаданные правились вручную и легко ломаются незаметно
  (длина title, потеря canonical, забытый alt, внешний шрифт).
- **Decision:** `scripts/seo_audit.py` — 161 проверка по всем страницам, sitemap,
  robots.txt и RSS; запускается в CI, при ошибках падает сборка. Правила зафиксированы
  в коде и описаны в `docs/SEO_AUDIT_2026-10-26.md`.
- **Consequences:** регрессии по метаданным видны в PR. Минус: при добавлении страницы
  её нужно внести в список `PUBLIC_PAGES`/`NOINDEX_PAGES` скрипта.

## D-013 — robots.txt и sitemap на подпути `github.io`

- **Status:** Superseded by D-016 · **Date:** 2026-10-26 · **Owner:** SEO-аудит
- **Context:** сайт жил на `bestdeejay-design.github.io/neo-consulting/`, поэтому
  `robots.txt` из репозитория роботы не запрашивают — нужен файл в корне домена.
- **Decision:** оставляем `robots.txt` как справочный файл с явным пояснением в
  комментариях, индексацию регулируем мета-тегом robots и sitemap, который
  отправляется вручную в Яндекс.Вебмастер и Search Console. В `robots.txt`
  сохраняем `Sitemap` и `Clean-param` для будущего переезда на свой домен.
- **Consequences:** не создаём иллюзию управления обходом; известное ограничение
  задокументировано. Полноценное решение — свой домен или root-репозиторий Pages.

## D-016 — Переезд на собственный домен neo-consalting.ru

- **Status:** Accepted · **Date:** 2026-10-27 · **Owner:** владелец + сборка
- **Context:** подключён собственный домен `neo-consalting.ru` (GitHub Pages +
  CNAME, DNS у REG.RU на ns1/ns2.reg.ru, A-записи → GitHub Pages, HTTPS
  enforced). Старый адрес `*.github.io/neo-consulting/` отдаёт 301 на домен.
  Все самоссылки внутри сайта (canonical, og:url, JSON-LD, sitemap, RSS,
  кнопки шаринга, README) ещё указывали на старый подпуть.
- **Decision:** заменить самоссылки на `https://neo-consalting.ru` по всем
  страницам, sitemap, фиду и README; обновить `BASE` в `scripts/seo_audit.py`
  (CI валидирует консистентность против нового домена); `robots.txt` теперь в
  корне собственного домена и работает штатно — комментарий в нём обновлён.
  Исторические записи (D-013, аудит 2026-10-26, CHANGELOG) не переписываются.
- **Consequences:** D-013 закрыт (Superseded). Осталось от владельца по
  `docs/SEO_INPUTS.md`: доступы в Яндекс.Вебмастер и Search Console, телефон/
  соцпрофили, карты (Яндекс Бизнес, 2ГИС).

## D-015 — Кластеры «зарплата», «регистрация», «АНО», «ОСНО»

- **Status:** Accepted · **Date:** 2026-10-26 · **Owner:** контент по запросу владельца
- **Context:** после двух денежных страниц владелец заказал ещё четыре кластера:
  зарплата и кадры, регистрация/закрытие ИП и ООО, отдельная страница для АНО
  и отдельная для ОСНО. Главную не расширяем — только материалы.
- **Decision:** четыре статьи в оболочке гайдов с FAQPage, OG, перелинковкой
  на услуги (`#pricing`, `#contacts`) и соседние разборы. Суммы и госпошлины —
  как ориентиры законодательства 2026, не оферта.
- **Consequences:** хаб — 13 материалов; sitemap — 15 URL. Каждую новую
  страницу по-прежнему нужно добавлять в `PUBLIC_PAGES`, sitemap и RSS.

## D-014 — Коммерческие страницы-кластеры вместо одной страницы услуг

- **Status:** Accepted · **Date:** 2026-10-26 · **Owner:** SEO-аудит
- **Context:** по итогам аудита главная закрывала только общие гео-запросы
  («бухгалтерский аутсорсинг СПб»), а два «денежных» кластера — смена бухгалтера
  и сравнение форматов ведения учёта — не были закрыты ни одной страницей.
  Лендинг расширять нельзя: он уже 17 секций, а конкурировать одной страницей
  по разным интентам неэффективно.
- **Decision:** добавляем две отдельные страницы в `materials/`
  (`smena-buhgaltera.html`, `shtatny-buhgalter-ili-autsorsing.html`) в общей
  оболочке статей: автор-человек, даты, FAQ-разметка, CTA на консультацию,
  перелинковка с главной, хабом и четырьмя существующими статьями.
  OG-карточки генерируются `scripts/make_og.py` в фирменном стиле.
- **Consequences:** сайт получает входы по коммерческим запросам без перегруза
  главной. Минус: каждую новую страницу нужно добавлять в `PUBLIC_PAGES`
  аудит-скрипта, в `sitemap.xml`, `feed.xml` и в хаб — иначе CI или полнота
  карты сайта сломаются.
